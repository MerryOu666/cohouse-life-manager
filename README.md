# 翻译质量评估：功能说明与使用示例

这是一份面向使用者的公开说明，介绍翻译质量评估能力的用途、输入要求和典型工作方式。

## 能解决什么问题

翻译质量评估用于判断机器翻译结果是否准确、自然、易懂，帮助团队：

- 比较不同翻译模型或引擎的效果
- 发现漏译、误译、术语不一致和语气问题
- 按统一标准对多条译文进行人工或模型辅助评估
- 汇总分数、分歧和典型案例，形成可复核的评估结论

## 支持的评估范围

- 产品、技术、运营、客服等常见领域文本
- 中译英、英译中及其他已准备好原文和译文的语言方向
- 单条样例评估和批量数据评估
- 两组候选译文的对比评估
- 对评分分歧进行复核，并保留最终判断依据

## 输入要求

推荐使用表格整理测试数据，每行至少包含：

| 字段 | 说明 |
| --- | --- |
| `source` | 原文 |
| `translation_a` | 候选译文 A |
| `translation_b` | 候选译文 B，可选 |
| `domain` | 文本领域，可选 |
| `language_pair` | 语言方向，可选 |
| `case_id` | 样例编号，可选 |

输入前建议：

1. 删除姓名、电话、邮箱、账号、密钥等敏感信息。
2. 统一空值、语言方向和领域名称。
3. 保留原文上下文，避免只截取无法独立理解的短句。
4. 为批量评估准备稳定的样例编号，便于回溯问题。

## 评估关注点

评估时通常从以下维度判断：

- **准确性**：是否正确表达原文含义，是否存在漏译、误译或事实变化。
- **完整性**：关键信息、限定条件、数字和专有名词是否保留。
- **流畅度**：目标语言是否自然、通顺，是否有明显机器翻译腔。
- **术语一致性**：同一概念在不同句子中是否保持统一表达。
- **语气与风格**：是否符合产品、技术、客服或其他指定场景的表达习惯。
- **可理解度**：目标读者能否快速、无歧义地理解译文。

## 典型使用示例

### 示例一：比较两个翻译版本

**目标**：比较同一批产品帮助文档由两个翻译引擎生成的结果。

**准备**：为每条数据提供原文、译文 A、译文 B，并标记领域为“产品文档”。

**结果**：获得逐条评价、总体分布、两组译文的优势差异，以及需要人工重点复核的样例。

### 示例二：评估单个翻译引擎

**目标**：了解客服话术翻译是否适合直接上线。

**准备**：提供原文和机器译文，补充语言方向及“客服”领域信息。

**结果**：识别语气不当、关键信息遗漏和用户可能误解的句子，并给出修改建议。

### 示例三：定位术语问题

**目标**：检查技术产品术语在一批译文中是否统一。

**准备**：提供带有产品名、功能名和技术术语的测试集。

**结果**：汇总术语不一致案例，区分术语错误与一般表达问题，便于补充术语表或改进翻译规则。

## 输出内容

一次完整评估通常包括：

- 逐条评估结果
- 各维度分数或等级
- 总体统计与通过率
- 候选译文之间的对比结论
- 评分分歧与复核结果
- 代表性问题样例
- 可执行的优化建议

## 使用建议

- 测试集应覆盖正常句、长句、数字、专有名词、否定句和上下文依赖句。
- 不要只看平均分，应同时关注严重错误和高频问题类型。
- 上线前建议单独复核涉及金额、时间、法律、医疗、安全和用户承诺的内容。
- 评估结论适用于所提供的测试集，不能直接等同于所有场景下的翻译效果。
